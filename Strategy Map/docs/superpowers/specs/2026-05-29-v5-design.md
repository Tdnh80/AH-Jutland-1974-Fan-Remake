## 1. 目标与范围

在 v4「搜索→接敌判定」内核之上,补齐队形系统、接敌后状态机、字母数字坐标、绝对时间、
操作日志,并新增**裁判机服务器联网**(双盲、全局视角)。全部模块都做,不砍范围、不分优先级
(用户明确要求)。地形数据(海岸/雷区/陆地)本轮**只预留配置结构,不填数据**。

### 已确认的决策(澄清对话结论)

| 项 | 决策 |
|---|---|
| 默认起始日期 | **1916-05-31 00:00**(贴合日德兰海战史实) |
| 日期输出格式 | **`DD/MM/YY HHMM`**(日/月/年),如 `31/05/16 0000` |
| 时间输入 | 支持三式:回合数 / 拍数(substep)/ HHMM |
| 坐标字母进位 | **A–Z, AA, BB, CC, DD**(共 30 行),非 Excel 进位 |
| 坐标四角 | 左上 A13、右上 A34、左下 DD-1、右下 DD19;以规则书中译搜索图为准 |
| 坐标 I/O | 显示/输入用「字母+数字」(如 `A13`);内部仍用 axial |
| 「中心」 | 抽象参考点,**不是旗舰**;是宏观/微观移动单位与相对坐标原点 |
| save/load | 升级为**全操作历史 + 每回合结果**的日志(可回放),不只最新状态 |
| compass turn | 用**「转向点前后 relocate」兜底**实现,不做精确曲线运动学 |
| 联网 | **裁判机服务器**(中心持全局视角,各方只见己方,天然双盲) |
| 侦察幕(8°) | 忽略,不实现 |
| 优先级 | 不排,全做 |

## 2. 架构总览

保持「纯领域引擎 / 表现层」分离(为联网与 GUI 铺路)。建议从单文件拆为:

```
fleet/
  hexgrid.py    # axial 数学 + 字母数字坐标编解码(纯函数)
  timekeep.py   # 绝对时间 <-> 回合/拍/HHMM/日期 互转
  model.py      # Ship / Fleet / Formation / Center(抽象中心)
  engine.py     # Game:调度、检测、接敌状态机
  journal.py    # 操作历史 + 每回合结果日志(save log / replay)
  viz.py        # matplotlib 全局图 + 接敌放大特写
  config.py     # 开发者调试 JSON(地图/地形/队形)加载
  cli.py        # REPL
  server.py     # 裁判机服务器(全局视角 + 双盲过滤)
  client.py     # 玩家客户端
```

引擎层(hexgrid/timekeep/model/engine/journal)**不依赖** matplotlib / 网络 / CLI。
拆分按 v4 现有分区顺势进行,机械迁移为主。每个文件单一职责,可独立测试。

依赖顺序(实现先后):基础层(hexgrid+timekeep)→ 模型层(model 中心+队形)→
流程层(engine 状态机)→ 持久化(journal)→ 表现(viz+config+cli)→ 联网(server+client)。

## 3. 模块设计

### 3.1 时间(timekeep)

- 内部以**绝对分钟**计(基准 epoch = 1916-05-31 00:00 = 第 0 分钟)。1 拍 = 10 分钟,
  1 回合 = 6 拍 = 60 分钟。
- 互转函数:`to_minutes(回合) / to_minutes(拍) / parse_hhmm` 与
  `fmt_date(min) -> "DD/MM/YY HHMM"`、`fmt_turn`、`fmt_sub`。
- 输入解析:`time` 类命令接受 `T<n>`(回合)、`sub<n>`(拍)、`HHMM`(当日时刻)三式;
  歧义以前缀区分。
- 输出:`list`/接敌报告/图标题统一三式并列(回合 + 拍 + `DD/MM/YY HHMM`)。
- 默认起算 epoch 可被开发者 JSON 覆盖。

### 3.2 坐标系(hexgrid)

- 内部保留 v4 的 axial `(q,r)` 与全部几何(像素映射、邻居、micro_position 等)不变。
- 显示坐标 = (字母, 数字),与 axial 的映射**已由规则书搜索图完全确定**(无需再标定):
  - 字母序列:`A..Z`(1–26)、`AA`(27)、`BB`(28)、`CC`(29)、`DD`(30),共 30 行;
    编解码 `letter_to_idx / idx_to_letter`(翻倍式,非 Excel 进位)。
  - **映射公式:`q = 数字 N`,`r = 字母行号 L`**(A=1 … DD=30),偏移取 0(原点随意)。
    据此:同一字母行(r 固定)水平向右 = 数字递增(q+1,E 方向);
    左上→右下(r+1,SE 方向)= 字母 +1、数字不变。
  - 校验(图上标注格,全部自洽):数字 15 线 E/I/N/S/X 同为 q=15;
    数字 20 线 C/H/M/W;数字 25 线 B/G/L;数字 10 线 K/O/T/Y;
    四角 A13=(13,1)、A34=(34,1)、DD-1=(-1,30)、DD19=(19,30)。
  - I/O 函数:`parse_cell("A13") -> (13,1)`、`cell_name(13,1) -> "A13"`。
- `parse_hex` 旧的 `q,r` 输入作为开发者/调试格式保留;玩家面默认 `A13` 格式。

### 3.3 中心抽象(model)

- 新增 `Center`:舰队的宏观/微观移动单位,持精确 `(x,y)` 与航向/速度;
  **取代 v4 里「旗舰 = 中心」的隐含假设**。
- `Fleet` = `Center` + `Formation` + ships。船只位置由「中心位置 + 队形 + 相对位置模式」推导。
- 接敌报告(7°)输出**中心**的微观坐标(hex + 格边 + 距格心),不再输出旗舰。
- 兼容:单纵阵 + 中心在排头时,行为与 v4 一致(回归测试守住)。

### 3.4 队形系统(model)

三种安置(`Formation` 子类型),均以「相对中心」的偏移描述:

- **line ahead(单纵)**:起点偏移(相对中心前后左右)+ 间距;默认排头。
- **line abreast(单横)**:起点(一侧头部)+ 展开方向(左/右)+ 间距。
- **echelon(梯形)**:起点 + 展开方向 + 展开角(单纵=0、单横=90)+ 间距。

两种相对位置模式(转向时**间距与梯形夹角恒不变**):

- **绝对相对位置**(参考地图地理北):机动后船只相对中心的**地图方位**不变。
  → 各舰独立转向,对应图中 **turn together / turn in succession**。
- **相对相对位置**(参考航向,极坐标感):机动后船只相对中心在**航向坐标系**下的方位距离不变
  (即转向后队形整体跟着转)。→ 对应 **compass turn**;**本版用 relocate 兜底**:
  在转向点前/后对中心与各船直接重定位到目标坐标,不模拟内外圈加减速曲线。

队形内机动:单纵 = 顺次(turn in succession,沿航迹弧长回退,v4 已有);
单横/梯形机动 = 以中心轨迹为基准 + 相对位置模式推导各船(绝对模式各船平移轨迹;
相对模式整形跟转)。

**0.66° 修复**:转向后单纵队列的轴线角度必须等于**新航向**(而非初始航向)。
归一化处理:任何航向变更后,以中心新航向重建队形朝向;写入文档「转向后队形状态」一节。

further(记录,不在本版强做):相对位置模式是否可用于「舰队与舰队之间」—— 预留为
未来扩展,接口上把「相对位置」抽象成可作用于任意 `Center` 的关系。

### 3.5 接敌后状态机(engine)

状态:`SEARCH`(常规搜索 step)→ `CONTACT`(接敌定格后)→ 回到 `SEARCH` 或进入线下战术。

- **接敌定格**:沿用 v4「回退到 >vis 拍 + =vis 投影」(0.6°/12° 不变,10min 离散非连续 CPA)。
- **保持接触**:接敌后双方仍在同格/多格内 → **相邻格若有其他船只,自动纳入接敌**,
  并计算其**驶入接敌格的微观时间**(除非该船航向明确驶离接敌格则不纳入)。
- **脱离接触**:双方分离 → 刷新回 `SEARCH`,重新输入编组。
- **同时多处结算**:一拍内可能有多组接敌;按涉及的中心配对**分组**,各组独立结算并在
  同一报告里并列输出(回答用户设问:支持同时多处)。
- **回合计数防 bug**(用户设问):接敌触发的回退/重置**只调整 `current_substep` 一次**,
  不得在多次/连续接敌时重复累加回合;状态机以「定格拍」为唯一时间锚,连续 encounter
  通过状态转移消解而非反复回退。加回归测试覆盖「连续接敌不叠加回合」。

### 3.6 操作日志(journal,替代 v4 save/load)

- 记录两条流:
  1. **操作历史**:每条玩家/开发者命令(含时间戳 = 当时绝对分钟、命令文本、参数)。
  2. **每回合结果**:每次 `step` 后的全量盘面快照(各中心位置/航向/速度/队形 + 接敌报告)。
- 存储格式:单个 JSON 文件,`{epoch, visibility, history:[...], turns:[...]}`;
  人类可读、可 diff。
- **回放**:`load <file>` 既能恢复到最新状态,也能 `replay <file> [到回合/拍]` 重演到任意点。
- 兼容:v4 刚加的 `to_dict/load_dict` 作为「每回合结果快照」的序列化基元复用;
  在其上叠加 history 流。tuple 反序列化守则(waypoints/anchor)继续适用。

### 3.7 表现与工具(viz / config / cli)

- **接敌放大特写图(0°)**:接敌时除全局图外,再出一张**只含涉及接敌的中心所在六角格**
  及其相邻格的放大图(自动裁剪范围 = 涉及格 + 1 圈邻格)。
- **开发者调试 JSON(4°)**:`config.py` 加载地图(尺寸/原点/地形占位)、初始舰队与队形、
  视距等;供调试与对局初始化。地形字段保留键、数据留空。
- **demo 收敛(0.5°)**:demo 随机走时加一个**隐性吸引因子**——回合数越大,双方中心
  朝彼此方向的偏置越强,保证长回合后趋于接敌(用于产样本)。直行偏置仍保留。
- **文档拆两版(1°/16°)**:`README.md` = 使用者版(白话);新增 `DEVELOPER.md` =
  开发者版(模型/坐标/状态机/协议)。**修 README 现有加粗渲染错误(5°)**。
- 坐标/时间显示全部切到新格式(`A13` + `DD/MM/YY HHMM` + 回合/拍)。

### 3.8 联网:裁判机服务器(server / client)

- **裁判机(server)**持有**全局 `Game`**(唯一权威状态、全局视角)。
- **玩家客户端(client)**:GB / GE 各一,只能下达己方命令、只接收**裁判过滤后**的视图
  (双盲:看不到对方位置,直到接敌报告)。
- 协议:基于操作日志的命令流。client → server 发命令;server 校验、应用、`step`、
  做双盲过滤后回推各方视图;接敌时向相关方推送接敌报告。
- 传输:简单 TCP/JSON line 协议(或 websocket),先实现可在局域网/本机多进程跑通。
- 复用:server 直接调用引擎层 + journal,不重写规则。
- 范围:实现裁判机 + 双客户端的命令/视图回路与双盲过滤;GUI(PyQt)不在本 spec,
  先 CLI 客户端跑通协议。
